# Task Runner & Agent Daemon: Problems and Fixes

This document collects the observed problems causing format/command execution failures (e.g., `mkdir` failing due to malformed JSON) and a prioritized, actionable fix plan with code patterns, tests, and notes.

---

## Symptoms

- Simple commands generated by the agent (mkdir, touch, etc.) fail with format errors or are not executed as expected.
- Logs show malformed JSON fragments or truncated model outputs.
- The system sometimes executes the wrong string (quotes unescaped, unmatched braces) or fails to extract a deterministic command.

---

## Root Causes (Observed in agent_daemon.py / task_runner.py)

1. Fragile LLM stop tokens
   - Stop tokens include characters like `\n}` or `.` or short newline sequences which can cause the small SmolLM model to stop early, producing truncated responses and incomplete JSON.

2. Naive JSON wrapping of raw LLM output
   - The runner prepends `{"cmd": "` to raw LLM output when it does not detect a JSON start. If the LLM output contains quotes, newline or `}` characters, this produces invalid JSON.

3. Brittle extraction/regex strategies
   - `_extract_json_obj` and extraction helpers use simple `find()`/`rfind()` and greedy regex patterns (e.g., `r'\{.*\}'`) that fail on nested braces, CoT prose, or extra text around JSON blocks.

4. Inconsistent parsing precedence
   - Code sometimes prefers regex-based extraction over safe `json.loads` on a properly extracted substring. There is no canonical pipeline: try parse → fallback to normalization → fallback to regex.

5. Insufficient sanitation/escaping
   - When building JSON by concatenation, inner quotes or backslashes are not escaped; when passing commands to `sh -c` they are not normalized or explicitly tokenized.

6. Weak logging and observability
   - Raw LLM output and normalization steps are not always logged in a way that makes debugging trivial (only limited raw/ai_raw entries without normalized JSON fields).

7. Stop/parse mismatch between model and parser
   - Prompt asks for strict JSON, but the LLM often includes prose or markdown fences; the parser is insufficiently tolerant.

---

## Fix Goals

- Ensure the task runner always produces a valid command string before execution.
- Avoid malformed JSON and truncated outputs by adjusting stop tokens and parsing logic.
- Sanitize and normalize the command to defend against injection and quoting bugs.
- Improve logging so failures are easy to inspect and reproduce.

---

## High-level Fix Plan (Prioritized)

1. Change stop tokens in LLM POST to avoid premature truncation.
2. Implement a robust JSON extraction and normalization helper.
3. Replace naive concatenation with `json.dumps` when building fallback JSON.
4. Sanitize the final shell command string before executing; preserve security checks.
5. Add improved logging of raw LLM output, normalized JSON string, and final command.
6. Add unit tests and a local CLI utility to validate the parsing logic against sample LLM outputs.

---

## Concrete Code Changes (patch snippets / patterns)

### 1) Stop token change

In `task_runner.py` and `agent_daemon.py` where the LLM request payload sets `stop` tokens, remove tokens that cause early cut-off such as `"\n}"` or single `"\n"`. Prefer explicit sentinel tokens you control.

Example (replace current `stop`):

```python
# safer stop tokens — keep minimal and explicit
payload = {
    "prompt": prompt,
    "n_predict": n_predict,
    "temperature": 0.1,
    "stop": ["<|im_end|>"]  # rely on model to complete JSON content
}
```

Notes:
- If you use a sentinel like `<|im_end|>` include it in the system/user prompt: "End your JSON response with the token `<|im_end|>`".
- Using fewer stop tokens reduces premature termination risk for very small models.

### 2) Robust JSON extraction helper

Add a bracket-matching extractor that finds the first balanced JSON object or array instead of greedy find/rfind or `r'\{.*\}'`.

Example helper:

```python
import json

def extract_first_json_object(text: str) -> Any | None:
    """Return the first balanced JSON object or array found in text, or None."""
    # search for '{' and '[' positions
    starts = []
    for i, ch in enumerate(text):
        if ch in '{[':
            starts.append((i, ch))
    for start_idx, ch in starts:
        stack = []
        opening = ch
        closing = '}' if ch == '{' else ']'
        for j in range(start_idx, len(text)):
            c = text[j]
            if c == opening:
                stack.append(c)
            elif c == closing:
                stack.pop()
                if not stack:
                    candidate = text[start_idx:j+1]
                    try:
                        return json.loads(candidate)
                    except json.JSONDecodeError:
                        break
    return None
```

Usage: call this first on raw LLM output and use the returned object if valid.

### 3) Build safe fallback JSON using json.dumps

If no valid JSON found, create a safe JSON object programmatically rather than concatenation:

```python
cmd_text = raw_output.strip()
# strip code fences if present
if cmd_text.startswith("```"):
    parts = cmd_text.split("```")
    if len(parts) >= 2:
        cmd_text = parts[1].strip()

fallback_json = json.dumps({"cmd": cmd_text}, ensure_ascii=False)
```

This guarantees well-formed JSON (quotes escaped).

### 4) Parse normalized JSON to extract command deterministically

Prefer:

```python
obj = extract_first_json_object(raw_output)
if obj and isinstance(obj, dict) and 'cmd' in obj:
    cmd_candidate = str(obj['cmd']).strip()
else:
    # use fallback_json
    parsed = json.loads(fallback_json)
    cmd_candidate = parsed.get('cmd','').strip()
```

Then sanitize command:

```python
def sanitize_cmd(cmd: str) -> str:
    cmd = cmd.strip()
    # strip surrounding quotes
    if (cmd.startswith('"') and cmd.endswith('"')) or (cmd.startswith("'") and cmd.endswith("'")):
        cmd = cmd[1:-1].strip()
    # reduce repeated spaces
    cmd = ' '.join(cmd.split())
    return cmd
```

### 5) Logging improvements

Record three fields in the task log for every step:
- `llm_raw` — raw LLM output
- `llm_normalized_json` — the normalized JSON string used for parsing
- `cmd_sanitized` — final sanitized command that will be executed

Do this with `log.write("ai_raw", raw=..., normalized=..., cmd=...)`.

### 6) Keep security checks & run safely

- Keep `is_safe_command` checks before execution.
- Continue to execute with `subprocess.run(["sh","-c", cmd], ...)` but after sanitization.
- For non-root callers, keep the `preexec_fn` privilege drop.

## Debugging checklist (if problems persist)

- Capture `llm_raw` and `llm_normalized_json` from the task log and reproduce `json.loads(llm_normalized_json)` locally.
- If parser fails, inspect the raw output for non-UTF8 bytes or unexpected control chars and add defensive cleaning (e.g., remove 0x00).
- If commands still fail at execution, log `stdout`, `stderr`, and `returncode` and run the sanitized command manually.

## Optional hardening & improvements

- Add a strict schema for model responses and require the model to return `{"cmd": "...", "explain": "..."}`. Enforce via `jsonschema` or simple key checks.
- Use a sentinel token (e.g., `<END_JSON>`) appended to the prompt and parsed to extract the result instead of relying on stop tokens.
- Consider restricting LLM outputs to only a whitelist of small atomic commands and mapping high-level intents to parameterized templates rather than free-form shell strings.
- Add a dry-run mode for the agent that writes the command to logs and returns success without executing (useful for CI).
